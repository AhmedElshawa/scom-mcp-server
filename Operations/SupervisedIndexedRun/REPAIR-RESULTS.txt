REVIEW-ONLY CORRECTED WRAPPERS - NOT RELEASE ACCEPTANCE

Scope: external fixed ZIP, isolated session artifacts only. No repository/PR
changes, SCOM collection, deployment, merge or publication to GitHub performed.

Root cause independently reproduced in Windows PowerShell 5.1:
Start-Process -PassThru with redirected files, polling HasExited followed by
WaitForExit and Refresh returned ExitCode=$null for a child that exited 7.
Casting that null to [int] produced 0. This was an actual exit-code-loss bug,
not an assertion/harness-only failure.

Fix:
- Retain the native process creation handle; GetExitCodeProcess retrieves the
  actual exit value without a nullable managed Start-Process exit-code cache.
- Create the worker with a Windows job-list attribute atomically, suspended
  until its creation handle is owned. Kill-on-close job contains descendants.
  No post-launch assignment window; no fallback to uncontained launch.
- Post-launch identity capture, arm/state writes and monitor setup are in a
  guarded try/catch/finally. Failure terminates the owned job and bounds empty-job
  verification to 5 seconds; an unverified stop is explicitly an error.
- Cleanup closes the job even when stop/verification fails. It never labels
  that failure as verified cleanup. It also bounds monitor termination/join.
- Monitor loss or stalled monitoring triggers an independently timed launcher
  stop. No unbounded WaitForExit remains in launcher/cleanup.
- Manual stop validates creation identity on a pinned process handle and kills
  through that handle, not a later PID lookup. It reports root stop pending
  launcher child join, not unconditional whole-tree completion.
- No snapshot-based descendant PID kills. Launcher job membership is the
  authority for child cleanup, including children created after a snapshot.
- Recheck CIM competitors for a live process before refusing launch, avoiding
  stale CIM entries for monitors already joined by a prior synthetic run.
- Parse Windows executable arguments and PowerShell command ASTs instead of
  searching entire command lines for marker text. An actual dotnet worker switch
  or profile invocation remains a conflict; strings, comments and test paths are
  not invocations. No process allowlist/exclusion for the harness was added.
- Identity checks pin a live handle without redundant CIM command-line lookups.
  Monitor timeout uses the current monotonic time after sampling, not stale
  pre-sample elapsed time; independent launcher stop limits are unchanged.
- Tests now resolve co-located files correctly and exit nonzero on any failed
  assertion. Existing nonzero==7 assertion is preserved, not weakened.

Limitations:
- Windows 10 / Server 2016+ job-list support and permitted nested job policy
  required. Unsupported/restricted hosts fail closed before worker execution.
- This wrapper still uses --worker-once. It is not sustained recurrence.
- Limits cover local worker/child memory and elapsed monitoring, not SCOM/SQL
  pressure. Source-owner telemetry/limits/approval still required separately.
- A stopped local job does not prove backend work cancellation or no commit.
  Publication/checkpoint/receiver and authenticated reader evidence stay separate.
- Output/state paths may contain identities, command lines or customer values;
  use approved protected local RunRoot. No ACL provisioning or auto-redaction
  of arbitrary synthetic/custom worker output is supplied.
- Abrupt launcher death closes its job (kernel cleanup), but cannot write
  a successful cleanup-verification record. Operators must retain unknown state.
- Review-only package has NOT been executed against a real worker configuration.
- Competitor discovery remains best-effort process inspection, not an atomic
  cross-launch mutex or proof of arbitrary indirect/dynamic wrapper invocations.
  Argument/AST matching does not execute or resolve dynamic PowerShell code.
